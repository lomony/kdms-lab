# KDMS PDF Merger (ASEC) – Test Report

Date: 16 Oct 2026 (UTC+7). App build: PDF.js 6.4.299 (legacy build) + @cantoo/pdf-lib 2.11.1.
Tester: KM Unit (automated, headless browsers on a Linux test machine via Playwright 1.64.1). Earlier manual UAT: 14–15 Oct 2026, KM Unit (Ayu – QA/QC, Erwin – UI/UX).

## How
- Test PDFs were generated by `security/tests/gen.py` (dummy content only): each source file has a distinct page width, so the merged file's page widths prove page order page by page.
- `security/tests/m.js` loads the app, adds the files, merges, downloads the output, and checks: page count; full page order; that no `/OpenAction`, document JavaScript, page `/AA` or JavaScript link actions remain in the output; every network request (any request to another host = fail); console errors; CSP violations (via a `securitypolicyviolation` listener); and browser dialogs (a PDF `app.alert()` would show up here).
- Final runs were served with the production headers proposed in `web.config` (`security/tests/hsrv.py`: CSP incl. `frame-ancestors`, `nosniff`, `X-Frame-Options`, `Referrer-Policy`, COOP, `.mjs` = `text/javascript`). The Firefox/WebKit edge-case runs used the same code with a plain static server.
- Timings = clicking **Merge** until the download link appears (files already selected). Memory = peak total RSS of all browser processes (Chromium only).
- **WebKit is Playwright's WebKit build (27.2), the engine closest to Safari. It is not real Safari** and no real iOS device was used. The "iPhone 14" and "Pixel 7" rows are device emulation (viewport, user agent, touch), not real phones.
- Edge = Microsoft Edge 155.0.4283.60 (stable channel, Linux).

### Other tests
| Test | Result |
|---|---|
| Two different files with the same name and size | Both kept (content SHA-256 de-duplication). Re-adding a byte-identical file is skipped with a visible notice. |
| `file://` (double-click `index.html`) | **Does not work**: Chromium blocks ES modules on `file://` (CORS). The page now shows a warning, and the docs say a web server is required. No external internet is needed in either case. |
| PDF JavaScript / form | No `app.alert` dialog in any browser. PDF.js is not given scripting and pdf-lib never runs scripts. The output has 0 JavaScript or automatic actions: document-level JS is not copied, and page `/AA` and JavaScript/Launch/SubmitForm link actions are stripped. The form field widget is kept as a copy only. |
| Inline styles | `index.html` has no `style=` attributes or `<style>` blocks. CSP `style-src 'self'` produced 0 violations in all runs (JS sets `element.style`, which CSP allows). |
| Live site (GitHub Pages, demo only) | See the commit notes and the final report. |

### Memory
- Merging 500 pages / 91.7 MiB in Chromium: peak RSS across all browser processes ≈ 0.86–0.88 GB, about 1 s.
- 69 pages / 33.7 MiB: ≈ 0.74 GB.
- Enforced limits: 100 MB total, 500 pages, 50 files.

## Known limitations
- Password-protected or encrypted PDFs, including owner-password-only files, are rejected. The user has to save an unprotected copy first.
- The output is a working copy. Digital signatures, fillable forms, bookmarks and PDF/A conformance may not be preserved.
- Not tested: real Safari or iOS devices, Windows/macOS desktop builds of the browsers, or IIS itself (only the same headers were tested).
